# Failures

What broke, what I tried, what fixed it. Matching lines are in `runs.jsonl` (`"ok": false`).

---

## F01 — Gemini TTS: HTTP 429 after 6 calls

- **What happened:** Generating narration for 10 shots, the 7th call failed with `429 You exceeded your
  current quota`. A quick retry a minute later worked, so I first assumed a per-minute limit.
- **Tried:** Added a 10 s pause between calls and exponential back-off (20 s, 40 s, 80 s). It still failed.
- **Root cause:** Reading the full error body: `GenerateRequestsPerDayPerProjectPerModel-FreeTier`,
  **limit 10 requests per day** for `gemini-3.8-flash-tts`, "retry in 13h". Waiting could not help.
  (The brief says Gemini TTS is free; it is, but only 10 requests per model per day.)
- **Fix:** `pipeline/narration.py` now tells a per-day 429 apart from a per-minute one. Per-minute is
  retried; per-day moves straight to the next model in the fallback list
  (`gemini-3.8-flash-lite-tts`, …), and the model actually used is logged. The last shot (s10) was
  generated by the fallback. Then E02 replaced Gemini with Addis AI as the main narrator.
- **Lesson:** Read the whole error body before choosing a fix. Caching per shot meant the 7 finished
  lines were never regenerated.

## F02 — Retry helper wasted 60 s retrying a daily quota

- **What happened:** After F01's fix, the retry helper still retried the daily-quota error twice
  (20 s + 40 s) before falling back.
- **Fix:** `with_retries(..., no_retry=(DailyQuotaExhausted,))` in `pipeline/common.py` raises those
  errors immediately.

## F03 — Addis AI: HTTP 422 `CLIENT_REQUEST_ID_REQUIRED`

- **What happened:** The first Addis AI call failed: `client_request_id is required for paid generation`.
  The docs listed it as optional.
- **Fix:** Send a fresh UUID as `client_request_id` on each request. It also makes a retried request
  idempotent, so a network retry is not billed twice.

## F04 — Image model defaults: light skin, wrong clothing, wrong object

- **What happened:** First reference sheet: light-skinned grandfather in a bathrobe-like wrap, two
  European-looking boys in shorts. First jebena test: a Western teapot with a lid. First s01: an
  American wooden cabin.
- **Tried / fixed:** Explicit descriptions — skin tone, "Habesha", "East African features", the gabi
  as a handwoven shawl with a border, the jebena by its shape, the house as plastered walls with a
  corrugated iron roof (E03, E05).
- **Still imperfect:** the model will not draw exactly five children (four every time). Accepted.

## F05 — Reference conditioning overrode the shot's composition

- **What happened:** s04 and s06 copied the layout of their reference images instead of following the
  shot prompt (E04).
- **Fix:** Removed `refs` from those two shots; regenerated only them (the cache kept the other eight).

## F06 — Subtitles wrapped to three lines and a centre crop cut the portraits in half

- **What happened:** In the first vertical cut, libass re-wrapped subtitles to three lines, and the
  9:16 centre crop of s06 cut both grandparents' portraits in half.
- **Fix:** Smaller subtitle font on a semi-transparent box, two long subtitles shortened; s06 changed
  from zoom to a pan from one portrait to the other. Only the s06 segment was re-rendered.

## F08 — Local network drop killed the Kaggle pollers while jobs sat in the queue

- **What happened:** Both Kaggle jobs (ACE-Step score, Wan 2.2 clips) were pushed and stayed in
  `QUEUED` for a long time. Overnight the laptop lost its connection; the status check raised
  `ConnectionError: Failed to resolve api.kaggle.com` and both local pollers crashed. On Kaggle the jobs
  were unaffected (still queued).
- **Fix:** `kaggle_job._status()` turns network errors into an "unknown, will retry" status instead of
  crashing. Each push writes a signature (hash of the script); a re-run whose script matches a job
  that is still queued or running **re-attaches** to it instead of pushing a duplicate.
- **Lesson:** a long-running remote job needs a poller that can be killed and restarted. The free
  GPU queue time, not generation time, was the real bottleneck.

## F09 — Kaggle jobs stuck in QUEUED for 12+ hours; then "Maximum batch GPU session count of 2"

- **What happened:** Both jobs were pushed with `"machine_shape": "NvidiaTeslaT4"` in
  kernel-metadata.json and never left `QUEUED`. Re-pushing without the setting failed with
  `Kernel push error: Maximum batch GPU session count of 2 reached`: the two stuck jobs still held both
  of the account's GPU session slots.
- **Tried:** The Kaggle CLI has no cancel command (`kernels -h`: list, files, get, init, push, pull,
  output, status, logs, update, delete).
- **Fix:** Deleted the two never-started notebooks (`kaggle kernels delete`), removed the
  `machine_shape` pin so Kaggle assigns any free GPU, and pushed again.
- **Lesson:** Free GPU capacity, not code, was the critical path. Pinning hardware is a bet that the
  pinned machine is free.

## F10 — No GPU for the score: Kaggle queue, then two Hugging Face Spaces

- **What happened:** Even without the machine pin (F09), both Kaggle jobs stayed `Queued…` on
  "GPU T4 x2" for over 40 minutes, on the last day before the deadline.
- **Tried 1 — ACE-Step 1.5 official Space** (`pipeline/music_hf.py`, gradio_client): the
  `/generation_wrapper` endpoint takes 49 UI values. Fixed in turn: missing required arguments (took
  all defaults from `view_api()`), `wav` not allowed (Space offers only mp3/flac). Then:
  `❌ Model not fully initialized. Missing components: ['model', 'vae', 'text_tokenizer',
  'text_encoder']` — the Space only loads its model from the web UI, not over the API.
- **Tried 2 — ACE-Step v1 Space** (`/__call__`, simpler API): failed on the server with
  `RepositoryNotFoundError`.
- **Fix:** `python pipeline/music.py colab` writes `notebooks/meskel_acestep_colab.ipynb` from the same
  storyboard parameters (caption, bpm, key, duration, seeds) — the brief's named backup. Run all on a
  Colab T4, download `music_out.zip`, unzip into `outputs/music/colab/`, then `music.py choose <n>`.
- **Lesson:** keep the job definition separate from where it runs. The same script body runs on Kaggle
  or Colab; only the working directory changes.

## F11 — Colab: three install failures, then no GPU; ACE-Step web app download is paid

- **Run 1:** `ModuleNotFoundError: loguru`. My script piped `pip install -e .` through `| tail -n 5`,
  which hid the install error and made the shell step report success.
- **Run 2 (install output visible):** every generation returned "Model not fully initialized";
  `initialize_service()` *returns* an error status instead of raising, so the script did not stop.
  Now the weights are downloaded explicitly and the returned status is checked.
- **Run 3 — the root cause:** `ERROR: Package 'ace-step' requires a different Python: 3.13.16 not in
  '<3.13,>=3.11'`. **Colab has moved to Python 3.13**; ACE-Step 1.5 declares support only up to 3.12,
  so pip installed nothing and each missing module (`loguru`, `vector_quantize_pytorch`) surfaced one
  at a time. Fix: `pip install --ignore-requires-python -e .` (notebook `meskel_acestep_colab_v2.ipynb`).
- **Run 4:** Colab refused a GPU: "No backend with GPU available" (free daily GPU limit reached after
  the earlier runs).
- **ACE-Step 1.5 Space, used in the browser:** both Format and Generate Music fail with
  "5Hz LM not initialized. Please initialize it first." — broken on the server side.
- **acemusic.ai** (the ACE-Step team's web app, advertised as free): generation works, but downloading
  any format requires a paid upgrade. Not used.
- **Kaggle:** the score job was still `QUEUED` after 98 minutes. I deleted the Wan 2.2 job (video is
  optional; Ken Burns is the accepted fallback) so any GPU Kaggle gives goes to the music.
- **Lesson:** the brief's warning was right — the stack moved under us within a day (Colab Python
  3.13, a broken official Space, a paywalled web app). Every attempt is logged in runs.jsonl or here.

## F07 — Tooling on Windows

- `kaggle` CLI 2.x failed with `ModuleNotFoundError: six` → installed `six` (added to requirements.txt).
- FFmpeg 9 removed `-vsync` → use `-fps_mode passthrough`.
- The FFmpeg `subtitles` filter breaks on Windows paths with a drive colon → run FFmpeg with the
  output folder as working directory and pass a relative `.srt` name.
